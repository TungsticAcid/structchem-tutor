## 二、总体定位与设计原则

### 2.1 一句话定位

> **把“晶典在线”从一款三维可视化工具，升级为一名“看得见、动得了、讲得清、练得会”的结构化学教学智能体。**

- **看得见**：Agent 能感知当前三维场景的一切状态（在看哪个晶体、开了哪些图层、视角停在哪、用户点了什么）
- **动得了**：Agent 能直接操控三维场景（切模型、开图层、亮空隙、跳对比、转视角），而不只是输出文字
- **讲得清**：Agent 讲解知识点时同步操控视图，把抽象概念演示出来
- **练得会**：Agent 讲完即出题、点击作答、即时解析、答错深讲，形成「讲解—练习—反馈—溯源」的学习闭环

**AI 能力是选用功能**：基础三维可视化永久免费且无需登录；AI 能力需消耗额度，用户也可接入自己的模型 API Key（BYOK）免额度使用。详见 §6.5。

### 2.2 为什么不能只“加一个聊天框”

赛事红线一明确排斥“单纯的问答型大模型”。市面上通用的化学问答机器人具备以下共性缺陷，也正是本方案要解决的问题：

| 通用问答机器人 | 本方案的智能体 |
|---|---|
| 只输出文字，学生读完仍无空间概念 | 直接操控 3D 场景，把答案“演示”出来 |
| 无法知道学生此刻在看什么 | 感知当前晶体、图层、视角、交互历史 |
| 需要学生主动提问 | 检测到学生卡壳时**主动介入** |
| 晶体参数靠模型记忆，易编造 | 所有结构数据**只从本地 COD 数据集读取**，物理上无法编造 |
| 千人一面 | 依个人学情画像调整讲解深度与推进节奏 |

### 2.3 四项智能体特性的落地方式（核心论证）

这一节是评审对照红线一的直接依据，也是方案的技术骨架。

#### （1）自主感知

Agent 在每次决策前，可读取当前页面的完整运行时状态——即 [viewer.js](../../H5/src/pages/viewer.js) 中 `_state` 对象的全部字段：

- **结构感知**：当前晶体 ID、化学式、晶系、空间群、点阵型式、结构基元、配位数
- **视图感知**：模型类型（`modelType`: ballStick / CPK）、晶胞显示模式、投影方式、当前视角四元数与球坐标
- **图层感知**：`showAtoms`、`showWireframe`、`showInterstices`、`showOctahedral`、`showTetrahedral`、`showSymmetry`、`showBonds`、`showAxes`、`showLatticePoints`、`showAtomLabels`、`showHydrogenBonds`、`showAuxiliaryBody`、`showAuxiliaryFace` 等十余个图层开关的当前状态
- **参数感知**：`atomScale`（原子大小）、`opacity`（透明度）、`stickRadius`（键粗细）、`fractionalShift`（分数坐标平移）、`equivalentIndex`（等效点系序号）、`atomVisibility`（各元素独立显隐）
- **行为感知**：停留时长、无操作时长、图层切换频次、重复查看的原子、点击弹窗记录

这使得 Agent 的每一次回应都建立在“学生此刻真正看到了什么”之上。

#### （2）智能决策

Agent 依据感知结果 + 学情画像 + 教学意图，选择下一步动作。决策输入包括：

- 学生当前的知识点定位（来自能力图谱映射）
- 历史错误模式（同一概念是否反复出错）
- 当前使用模式（自主探究 / 演示模式）
- 教学约束（本课程当前进度、教材章节对应关系）

决策输出不是一段文字，而是**一组工具调用 + 一句讲解**。

#### （3）主动服务

这是区别于被动问答的关键。触发规则示例：

| 感知信号 | 主动行为 |
|---|---|
| 同一晶体停留 > 45 秒且无任何操作 | 主动询问：“这个结构的八面体空隙分布是难点，要我打开给你看看吗？” |
| 反复开关同一图层 ≥ 3 次 | 主动解释该晶体学含义（如“你正在反复切换点阵点图层——它的作用是帮你识别点阵型式”） |
| CPK 与球棍模型来回切换 ≥ 3 次 | 主动对比讲解两种模型各自揭示的结构信息 |
| 反复点击同一元素原子 | 主动讲解该元素的配位环境与离子半径比 |
| 开启演示模式后长时间未翻页 | 询问是否需要补充讲解，或提示下一步操作 |

**关键点**：主动服务的每一条触发都对应一个**晶体学教学痛点**，而非通用的“猜你喜欢”。

#### （4）迭代优化

- **个人学情画像**：以能力图谱的 8 个知识点节点为坐标，记录每次交互的命中与错误，在 `localStorage` 持久化（符合数据最小化原则，无个人身份信息）
- **自适应讲解深度**：同一知识点对“新手”给出完整引导式讲解（逐步演示 3-4 个动作），对“已掌握”的学生直接给结论 + 抛出挑战性问题
- **匿名化群体反馈闭环**：聚合匿名使用数据形成热力图，可看到“多数使用者在‘空隙与堆积方式对应关系’这一节点普遍薄弱”，据此调整教学设计与讲解策略
- **知识库迭代**：教师对 AI 生成内容的修改记录回流，作为 Prompt 与知识库的优化依据

### 3.2 关键设计：`scene-bridge.js` —— 智能体的“手”

这是整个方案**最具创新性的技术设计**，也是“区别于问答型大模型”的物理实现。

现有 `ViewerPage` 的 `_state` 对象包含了 30 余个可调状态字段，且已有一整套事件处理方法（`_onLayerChange`、`_onModelTypeChange`、`_onEquivalentChange`、`_onAtomVisibilityChange` 等）。`scene-bridge` 的职责是：

1. **反向调用现有事件处理器**：Agent 的操控指令不新写渲染逻辑，而是复用页面已有的状态变更方法，保证「AI 操作」与「用户手动操作」走完全相同的代码路径——这既降低了开发量，也保证了行为一致性（用户手动能做的，AI 都能做）。
2. **暴露受控动作白名单**：Agent 只能调用白名单内的动作，防止越权改变页面结构（例如不能跳转到任意 URL）。
3. **动作与晶体学概念的绑定**：每个动作携带教学语义标签。这是本方案的设计精华——

| 受控动作 | 目标 `_state` 字段 | 绑定的晶体学概念 |
|---|---|---|
| `setModelType('cpk')` | `modelType` | 原子半径、空间利用率、紧密堆积 |
| `setModelType('ballStick')` | `modelType` | 化学键、配位环境、连接关系 |
| `toggleLayer('interstices')` | `showInterstices` | 空隙的形成与分布 |
| `toggleLayer('octahedral')` | `showOctahedral` | 八面体空隙、配位数 6 |
| `toggleLayer('tetrahedral')` | `showTetrahedral` | 四面体空隙、配位数 4 |
| `toggleLayer('latticePoints')` | `showLatticePoints` | 点阵型式（P/I/F/C/H） |
| `toggleLayer('symmetry')` | `showSymmetry` | 对称元素、空间群 |
| `toggleLayer('auxiliaryBody')` | `showAuxiliaryBody` | 体对角线、晶胞几何 |
| `toggleLayer('cellFace')` | `showAuxiliaryFace` | 面对角线、密堆积方向 |
| `setAtomVisibility(elem, false)` | `atomVisibility` | 子晶格、结构基元 |
| `setEquivalentSetting(i)` | `equivalentIndex` | 等效点系、原点选择 |
| `setOpacity(v)` / `setAtomScale(v)` | `opacity` / `atomScale` | 内部结构透视 |
| `setView(preset)` | 视角参量 | 特定方向的密堆积观察 |

> **评审价值**：通用问答模型无法产生这种“动作—概念”映射。这是教学智能体依托领域工具才能实现的创新，直接对应「创新优化性」20 分。

**设计要点：所有改动均为“增量式”**——现有渲染、交互、数据加载逻辑一行不改，Agent 层通过接口调用复用它们。这保证了最低的回归风险。

## 四、核心场景设计

**本项目不区分教师端与学生端。** 所有 AI 能力面向同一用户角色开放，功能互相兼顾——教师可以用练习板块布置随堂测，学生也可以用演示模式复现教师在课堂上演示过的序列。这一决策既压缩了三周内的开发量，也让工具在真实教学中更灵活（同一位使用者既教也学）。

四个场景按优先级排序，§4.1–§4.3 为 MVP，§4.4–§4.5 为二期规划（写入参赛材料以体现方案的延展性）。

### 4.1 问答练习板块 ★MVP　（核心功能｜对应赛道方向 1、方向 4）

**痛点**

- 学生看懂了三维结构，但做题时仍然不会——「看得懂」与「答得对」之间存在鸿沟
- 教材习题与三维模型脱节，做题时无法回看结构验证
- 做错了只看标准答案，不知道错在哪一类认知上，同类错误反复出现
- 通用刷题工具与本校课程、与本工具的三维场景完全无关

**方案**：构建「**讲解 → 练习 → 反馈 → 溯源 → 复述**」的完整学习闭环，全程与三维场景深度耦合。

#### 第 1 步 · AI 讲解知识点

学生选择或直接输入知识点（如“最密堆积的空隙分布”），AI 给出结构化讲解，**讲解过程中同步操控三维场景**：

- 自动切换到最合适的晶体（如 Cu 型）
- 打开对应图层（空隙 / 点阵点 / 对称元素）
- 分步解说，每一步对应一个明确的视图状态

讲解遵循「费曼式」表达原则：**先给直观图像，再引入术语定义**，避免术语堆砌。讲解卡底部提供「再讲一遍」「换个晶体看」「我懂了，出题吧」三个动作，把节奏控制权交给使用者。

#### 第 2 步 · AI 出题

讲解结束后，AI 基于**刚讲的知识点 + 当前晶体数据**生成练习题：

- 题干 + 4 个可点击选项（移动端大按钮，触控友好）
- 每题标注：对应知识点（能力图谱节点 C1–C8）、难度层级、数据来源

题目分两类，**生成机制完全不同**：

| 题型 | 生成方式 | 可靠性 |
|---|---|---|
| **数据驱动题** | 由程序从晶体数据**计算**生成。如“每个球周围有几个八面体空隙”→ 读 `interstices.octahedral.positions` 的长度算得；“NaCl 晶胞含几个 Na⁺”→ 从分数坐标统计 | 答案物理上不可能错 |
| **概念题** | 由模型生成，答案须能在本地知识库中找到依据，否则丢弃重生成 | 双源校验 |

#### 第 3 步 · 可点击作答 + 即时反馈

点击选项后立即判定，展示一张完整的反馈卡：

- **正误标记**（无论对错都不直接跳到下一题）
- **解析**：为什么这个选项对，其他选项分别错在哪
- **晶体结构直达链接** ★：若题目与具体结构相关，给出跳转按钮，点击后直接打开对应三维视图**并预置好观察状态**——例如自动打开八面体空隙图层、切到最能看清的角度。这是本板块与普通题库最直观的差别：**做题时能立刻回到结构里自己验证**。
- **关联知识**：链接到相关知识点，可继续学习

#### 第 4 步 · 答错则进一步讲解

答错时不只给正确答案，而是走完整的诊断流程：

1. **判断错误类型**：概念混淆 / 数据记错 / 计算失误 / 空间想象偏差
2. **自动操控三维场景，把错误“演示”出来**（与 §4.2 的错误可视化诊断共用同一机制）
3. **针对性追加讲解**，只补学生缺的那一环，不重复已掌握的部分
4. **出同知识点的变式题**检验是否真正纠正

> **示例**：学生答“Mg 型晶体中每个球周围有 8 个正八面体空隙”
> → 判定为「概念混淆：把八面体的 8 个面当成了空隙数」
> → 自动打开空隙图层、高亮中心球周围的空隙、旋转视角
> → 引导：“我们一起数一数……是 6 个。八面体有 8 个**面**，但空隙个数由**堆积方式**决定。”
> → 变式题：“那么 Cu 型（A1）中每个球周围有几个正八面体空隙？”

#### 第 5 步 · 反向讲解（费曼学习法）

费曼学习法的精髓是**以教代学**——真正掌握的标志是能用平实语言讲清楚。因此在答对之后增设反向环节：

- AI 邀请：“你已经答对了。试着用你自己的话说说，为什么 Mg 型是六方最密堆积，而 Cu 型是立方最密堆积？”
- 用文字或语音作答
- AI 判断表述中的概念漏洞（如“把 A1 与 A3 的层序记号记反了”“混淆了 ABAB 与 ABCABC”），**给出针对性补充 + 对应的三维观察动作**
- 表述完整则给予肯定并解锁下一难度

这一步把「选择题的**识别性**掌握」推进到「**生成性**掌握」，是本板块区别于普通刷题工具的关键设计，也同时对应赛道方向 1 的“自主探究式学习”与方向 4 的“学生能力评价”。

> 📌 **待对齐事项**：“蒸馏网络”上若有现成的**费曼学习法 skill**，建议对齐其提示词结构与流程规范以提升设计规范性。该 skill 的具体来源与规范待补充确认。

#### 功能清单

| 功能 | 说明 | 优先级 |
|---|---|---|
| 知识点讲解 | 结构化讲解 + 同步操控三维场景 | ★MVP |
| 自动出题 | 数据驱动题（可校验）+ 概念题（双源校验） | ★MVP |
| 可点击作答 | 移动端友好的大按钮选项 | ★MVP |
| 即时反馈与解析 | 正误 + 解析 + 错项逐个分析 | ★MVP |
| 晶体结构直达链接 | 一键跳转并预置观察状态 | ★MVP |
| 答错深入讲解 | 错误归因 + 可视化诊断 + 变式题 | ★MVP |
| 反向讲解（费曼） | 学生复述，AI 判断漏洞 | ★MVP |
| 错题本 | 自动收录错题，按知识点分组 | ☆二期 |
| 学习进度 | 知识点掌握度可视化 | ☆二期 |

#### 防幻觉设计（本板块最关键）

**出题是最容易暴露模型幻觉的环节**——错误的题目或答案会直接误导学生，且比问答场景更严重（学生会把错误内容当标准答案记住）。对策有四条：

1. **优先数据驱动出题**：凡涉及数值的题目（配位数、空隙数、晶胞原子数、空间利用率、晶格参数），一律由程序从晶体数据计算生成，**不让模型参与数值生成**。
2. **概念题双源校验**：模型生成的概念题，其答案须能在本地知识库中找到依据，否则丢弃重生成。
3. **答案与解析分离生成**：先冻结答案，再生成解析，避免“解析与答案互相圆场”这类隐蔽错误。
4. **人工复核入库**：进入正式题库的题目须经人工审核（见 §6.1）。

> 这四条正面回应了赛事方向 3 点名的“AI 智能体生成内容的事实性偏差（幻觉问题）”，可作为「技术规范性」的核心论据。

> 📄 **详细设计**：出题引擎的完整技术设计（题型模板库、干扰项生成规则、错因分类体系、数据校验层、开发分解）见配套文档《出题引擎技术设计.md》。其中包含一项关键的可行性核查结果——`coordination` 字段格式不统一（从纯数字到自然语言混杂），不能直接解析出题，需人工整理结构化对照表。

### 4.2 场景答疑与主动服务 ★MVP　（对应赛道方向 1）

**痛点**：学生课后自学晶体结构时遇到卡点，无人可问；教材插图是静态的，无法验证自己的空间想象是否正确；不知道该练什么、练到什么程度。

**方案**：在浏览三维结构时可随时提问，Agent 结合当前场景作答并**直接操作视图**；检测到卡壳时**主动介入**；通过随堂小测诊断掌握度。

#### 典型交互 A（答疑）

> 使用者（正在看金刚石）： “为什么金刚石的碳原子是 4 配位？”
>
> Agent：*（自动开启化学键图层，高亮中心碳及其 4 个近邻）*
> “你看高亮的这个碳原子——它周围的 4 个碳并不在同一个平面，而是指向正四面体的 4 个顶点。这个角度是 109°28′。我把正四面体框出来给你看。”
> *（开启辅助线图层，画出四面体轮廓）*
>
> 使用者：“那为什么不是 6 配位？”
>
> Agent：*（切换为 CPK 模型）* “从空间填充看，碳的共价半径在这里只能容纳 4 个近邻填满空间。对比一下 NaCl——那里的 Na⁺ 是被 6 个 Cl⁻ 包围的，要看看差别吗？”
> *（提供“对比查看”按钮，一键跳转对比页）*

#### 典型交互 B（主动服务）

> *（已查看 Mg 型晶体 50 秒未操作）*
>
> Agent（浮出提示条，不打断操作）：“最密堆积结构里，空隙分布常常容易记混。要我把四面体空隙和八面体空隙同时打开对比一下吗？”
> *（点击「好」/「不用」）*

#### 典型交互 C（错误可视化诊断）—— ★ 本方案的原创设计之一

这一机制与 §4.1 练习板块共用，是通用问答模型无法复现的核心差异点：

> Agent：“Mg 型（A3 六方最密堆积）中，每个球周围有几个正八面体空隙？”
>
> 使用者：“8 个。”
>
> Agent：*（**自动执行诊断动作**：打开八面体空隙图层，切换 Ball&Stick，从俯视角度旋转到最能看清的位置，高亮中心球周围全部八面体空隙）*
> “我们一起数一数——你看这些橙色标记，它们都落在中心球周围。现在把视角转到侧面再看一次。”
> *（自动旋转视角 90°）*
> “数出来了吗？是 6 个。**你的答案里有 8，很可能是把‘八面体空隙’和‘8’这个数字联系起来了**——八面体有 8 个面，但空隙的个数由堆积方式决定，不由顶点数决定。这是很常见的混淆点。”

**这项设计的价值**：

- 通用问答模型只能输出“正确答案是 6，因为……”，使用者看到的是文字
- 本方案让错误**变得可视化、可自行验证**，是探究式学习而非灌输
- Agent 不仅纠正答案，还**识别错误的认知根源**（“把八面体的面数当成了空隙数”）——这是教学智能体相对通用模型的核心优势
- 同时覆盖赛道方向 4 的「问题诊断」「评价反馈」，可支撑两个方向的申报叙事

#### 关键功能

| 功能 | 说明 | 优先级 |
|---|---|---|
| 场景问答 | 结合当前晶体 + 视图状态的答疑，回答中直接操控视图 | ★MVP |
| 主动介入 | 基于停留时长/重复操作的触发规则（见 §2.3-3） | ★MVP |
| 引导式讲解 | 分步骤演示 + 逐步提问，而非一次性给答案 | ★MVP |
| 错误可视化诊断 | 答错时自动切换到能揭示错误根源的视图状态 | ★MVP |
| 学情画像 | 记录知识点掌握度，调整讲解深度 | ★MVP（基础版） |
| 自适应难度 | 依画像动态调整题目难度与讲解详略 | ☆二期 |
| 学习路径推荐 | “你已掌握 A、B，建议下一步学 C” | ☆二期 |

### 4.3 演示模式 ★MVP　（对应赛道方向 2）

> **定位说明**：演示模式是一个**功能开关**，不是“教师专属入口”。任何人（教师课堂演示、学生自己回看、录制讲解视频）都可以启用。这不影响“不区分教师端学生端”的总体决策。

**痛点**：课堂演示晶体结构时，需要一边讲解一边手动操作图层开关、切换模型、旋转视角，操作与讲解互相打断；复杂结构的演示序列难以复现；不同演示者对同一知识点的演示路径不一致。

**方案**：用自然语言提出教学意图，Agent 自动编排并执行一整套三维演示序列。

> 输入：“给学生讲一下 NaCl 里为什么是 6 配位。”
>
> Agent 的执行序列（分步自动播放，可暂停 / 回退）：
> 1. 跳转到 NaCl 查看器（若不在该页）
> 2. 切换为球棍模型 → 讲解：“球棍模型突出连接关系”
> 3. 关闭线框与坐标轴，降低干扰
> 4. 高亮一个 Na⁺ 及其周围 6 个 Cl⁻
> 5. 打开八面体空隙图层 → 讲解：“Na⁺ 恰好落在 Cl⁻ 构成的正八面体空隙中心”
> 6. 切换为 CPK 模型 → 讲解：“从空间填充看，离子半径比恰好允许 6 个 Cl⁻ 贴合一个 Na⁺”
> 7. 切回球棍 + 打开对称元素 → 延伸：“这也是 Fm-3m 空间群中 Na⁺ 占 4b 位的原因”
>
> 全程只需点“下一步”，无需手动操作界面。

#### 关键功能

| 功能 | 说明 | 优先级 |
|---|---|---|
| 教学脚本编排 | 自然语言 → 动作序列（Agent 规划） | ★MVP |
| 分步播放控制 | 播放/暂停/上一步/下一步/跳到某步 | ★MVP |
| 脚本库 | 常用脚本保存复用（如“讲密堆积”“讲空隙”“讲点阵”） | ★MVP |
| 演示模式 | 隐藏编辑性 UI，只留演示控制条，适配投影仪 | ★MVP |
| 课后导出 | 演示序列导出为可分享链接，课后可复现 | ☆二期 |
| 跨晶体串联演示 | “从 NaCl 讲到 CsCl 再讲到 ZnS”，自动串场 | ☆二期 |

**评审价值**：直接对应赛道原文“备课授课、课堂互动、场景模拟”，且“教学脚本可复现 + 可共享”显著区别于通用问答。

### 4.4 课程资源与知识库 ☆二期　（对应赛道方向 3：AI+教学资源建设）

**方案**：

1. **结构化知识库（权威、零幻觉）**：23 套晶体数据全部来自 COD 数据库，以结构化字段存储，Agent **只能通过工具读取，不能凭记忆生成**。这是物理层面的防幻觉——模型根本没有编造参数的“机会”。
2. **文本知识库（RAG）**：上传自有讲义、教学大纲、习题集，构建课程专属知识库。Agent 回答超纲或概念性问题时先检索、再作答，并附来源。
3. **资源生成与人工复核**：可要求生成课件要点、练习题、对比案例、三维演示脚本，生成内容进入**待审队列**，确认后方可发布（见 §6.1）。

**版权风险提示**：知识库不得直接上传受版权保护的教材原文（如周公度《结构化学基础》等）。建议仅使用：自编讲义、自出习题、开放的 COD 数据、享有著作权的课堂材料。此项直接关系淘汰红线中的「知识产权争议」。

### 4.5 学习诊断 ☆二期　（对应赛道方向 4：AI+教学评价改革）

**方案**：

1. **知识点能力图谱**（同时是赛事支撑材料点名要求提交的“能力图谱图纸”）
   - 横向：结构化学晶体部分的 8 个核心知识点（C1–C8，见配套文档 §5.1）
   - 纵向：23 种晶体结构在 8 个知识点上的分布矩阵
   - 每个节点标注：所属章节、难度层级、对应的 3D 观察动作、对应的检测题目
2. **掌握度计算**：每次交互（查看晶体、开启图层、答题、纠错、反向讲解）映射到图谱节点，按加权规则计算掌握度
3. **诊断报告**：个人报告（薄弱知识点 + 推荐复习路径 + 一键复现对应三维场景）与匿名化班级报告（热力图 + 共性问题）
4. **教学优化建议**：对使用者输出“建议下次课重点讲解 XX 节点，班级掌握度仅 42%”

> 完整的能力图谱设计详见配套文档《参赛执行清单.md》第五章。

| 工具名 | 功能 | 返回内容 |

| `getCurrentScene` | 获取当前三维场景完整快照 | 晶体 ID、模型类型、全部图层开关状态、视角参量、当前等效点系、原子显隐表 |
| `getInteractionTrace` | 获取近期交互轨迹 | 停留时长、无操作时长、图层切换历史、点击过的原子列表、模型切换次数 |
| `getLearningProfile` | 获取学情画像 | 各知识点掌握度、历史错误记录、学习偏好（见图表优先/文字优先） |

### 5.3 操控类工具（新增）—— 智能体的“手”

| 工具名 | 参数 | 作用 |
|---|---|---|
| `controlViewer` | 动作名 + 参数值 | 通用操控入口，动作白名单见 §3.2 表格 |
| `highlightAtoms` | 元素列表 / 坐标范围 | 高亮指定原子或配位环境 |
| `startGuidedTour` | 步骤序列 | 启动分步引导演示 |
| `startDemoSequence` | 教学脚本 ID | 启动演示模式 |
| `navigateTo` | 路由路径 | 跳转页面（查看器/对比页），受路由白名单约束 |

### 5.4 教学类工具（新增）

服务于 §4.1 练习板块与 §4.2 答疑的核心工具。

| 工具名 | 功能 | 备注 |
|---|---|---|
| `explainKnowledgePoint` | 讲解指定知识点，返回讲解步骤序列（每步含解说词 + 应设置的场景状态） | 讲解与操控打包返回，保证“讲什么就看什么” |
| `generateQuiz` | 基于知识点 + 晶体数据出题，返回题干、选项、正确答案、知识点节点、难度 | 数值题走数据计算路径，概念题走模型路径 |
| `checkAnswer` | 判定答案，返回正误、错误类型归因、建议的诊断动作 | 错误类型：概念混淆/数据记错/计算失误/空间想象偏差 |
| `diagnoseError` | 执行错误可视化诊断，返回应设置的场景状态 | 与 §4.2 共用机制 |
| `generateVariantQuiz` | 生成同知识点的变式题，检验是否真正纠正 | 答错并讲解后调用 |
| `judgeExplanation` | 判定费曼式反向讲解的表述，返回概念漏洞清单与补充建议 | §4.1 第 5 步使用 |
| `getRelatedCrystalLink` | 返回与该题相关的晶体 ID 及**预置观察状态**，供一键跳转 | 反馈卡上的「去看结构」按钮 |
| `recordLearningEvent` | 记录学情事件到画像（知识点、事件类型、正误、时间戳） | 迭代优化的数据来源 |
| `searchKnowledge` | RAG 检索课程知识库 | ☆二期 |

### 5.5 防幻觉机制（技术规范性得分点）

赛事明确点名“幻觉问题”，本方案提供**四重防护**：

1. **数据源隔离**：所有晶体结构参数（晶格常数、原子坐标、空间群、配位数）只能从本地 COD 数据集经工具读取，**模型提示词中明确禁止凭记忆输出任何数值**。
2. **引用强制**：Agent 输出的每一个结构参数都必须标注工具来源，无来源的参数不允许出现在回答中。
3. **ID 溯源铁律**（继承自小程序版已有约束）：`crystalId` 必须来自上游工具返回的原值，禁止编造或从自然语言推断。
4. **知识库边界**：超纲问题明确回复“这不在本课程知识库范围内”，不允许模型自由发挥。

## 六、人机协同、安全与合规

对应评分项「技术规范性」25 分，赛事合规总则第 1 条亦明确要求“AI 生成教学资源、方案必须人工审核，建立错误修正、风险预警流程”。

### 6.1 人工复核机制

| 内容类型 | 复核要求 |
|---|---|
| 即时答疑 | AI 直接输出，但界面明确标注「AI 生成，仅供参考」 |
| 随堂题与解析 | AI 生成 → 人工复核后方可进入正式题库；生成态即可即时练习，但标注「未经审核」 |
| 教学演示脚本 | AI 生成 → 人工确认后保存到脚本库 |
| 教学资源（课件要点、案例） | 强制进入待审队列，人工批准后才发布 |
| 学情诊断报告 | 仅使用者本人可见个人数据 |

**复核留痕**：所有 AI 生成内容与人工修改记录写入审计日志，可追溯。

### 6.2 数据安全与隐私保护

| 措施 | 说明 |
|---|---|
| 数据最小化 | 不采集姓名、学号、手机号等个人身份信息；学生以随机匿名 ID 标识 |
| 本地优先 | 学情画像存储在浏览器 `localStorage`，默认不上传 |
| 传输脱敏 | 上报模型的内容不包含任何个人身份信息与班级名单 |
| 输入输出双向过滤 | 敏感词过滤 + 内容安全审核，双向把关 |
| 不采集未成年人数据 | 本工具面向高校，明确使用范围 |

### 6.3 模型与平台选型

**模型选择建议**：优先选用**已完成国家生成式人工智能服务备案的国产大模型**（如 DeepSeek、通义千问 Qwen、智谱 GLM、豆包、Kimi 等）。理由：

1. **合规优先**：赛事原文鼓励“优先使用符合国家数据安全、网络安全要求的国产人工智能工具和教育平台”，此为明确的加分导向
2. **中文教学语境**：国产模型对中文化学教学术语的理解更好
3. **成本与速度**：国产模型 API 成本低，适合教学场景的高频调用
4. **需在参赛材料中如实说明**所使用的平台、工具、模型及其技术来源（赛事明确要求）

> ⚠️ **部署合规风险提示**：现有 H5 部署于 Vercel（境外平台），若配合境外模型调用，可能涉及教育数据出境问题。**处理方式**：
> - **默认路径**：模型调用一律经自建 Serverless 后端代理（`/api/chat`），后端只转发脱敏后的对话内容，不传任何个人数据；
> - **BYOK 路径**：凭据与对话内容不经本项目服务器（见 §6.5），从架构上规避了平台侧的数据出境问题；
> - 参赛材料中说明后续将迁移至国内云平台。

### 6.4 全链路审计

| 审计项 | 内容 |
|---|---|
| 工具调用日志 | 时间、工具名、参数、返回状态 |
| 模型调用日志 | 时间、模型名、Token 用量、是否触发安全过滤 |
| 内容审核日志 | 拦截记录、人工复核记录、修改前后对照 |
| 学情事件日志 | 匿名 ID、知识点、事件类型、时间戳 |

### 6.5 额度体系与自带 API Key（BYOK）

**AI 能力是选用功能**，不影响基础三维可视化的使用。启用 AI 需要消耗额度；使用者也可接入自己的模型 API Key 免额度使用。这一节归入本章，是因为其核心考量同样是**安全与滥用防护**（而非单纯的计费）。

#### 使用层级

| 层级 | 说明 | 额度消耗 |
|---|---|---|
| 基础功能 | 全部三维可视化、图层控制、对比、设置 | 无（免费，无需登录） |
| AI 体验额度 | 新用户赠送一定额度（如 N 轮对话 / M 道练习题） | 消耗平台额度 |
| 自带 Key（BYOK） | 填入自己的模型 API Key，直连模型厂商 | 不消耗平台额度 |
| 会员模型（规划中） | 更高性能模型、更长上下文、高阶教学功能 | 会员制 |

#### 额度设计要点

- **计量单位**：建议用**对话轮次**而非 Token 数——对使用者更直观，也便于按教学动作差异化加权（讲解 1 轮、出题 1 轮、反向讲解评判 2 轮）
- **额度可见**：AI 面板常驻显示剩余额度，临界时提示
- **本地记账 + 服务端校验**：前端负责展示与即时反馈，服务端做权威扣减（防止前端篡改）
- **防滥用**：单用户速率限制、异常调用模式检测、赠送额度的一次性约束

#### BYOK 设计（关键安全点）

API Key 是敏感凭据，**绝不能上传、存储或记录**。设计要点如下。

**凭据存储**

- 仅存于浏览器 `localStorage`，**从不发送至本项目服务器**
- 界面中默认掩码显示，提供「清除 Key」按钮
- 提供「仅本次会话有效」选项（存入 `sessionStorage`，关闭标签页即失效），适用于公共设备
- 保存前提示风险：本机存储、勿在公共设备保存

**调用路径（推荐前端直连）**

- 前端直接向模型厂商端点发起请求，本项目全程不经手凭据与对话内容——隐私最优，也顺带规避了平台侧的数据出境问题
- 若某厂商端点不支持浏览器跨域调用，则退化为经 `/api/chat` **透传**：Key 只在单次请求的内存中转发，**不落盘、不记日志、不进审计日志**

**必须向使用者明示**

- BYOK 模式下，对话内容直接发送至所选模型厂商，其数据处理遵循该厂商的隐私政策，本项目不承担该环节的数据责任
- 此声明须同时写入页面提示与隐私说明

#### 商业化延展与教学普惠的平衡

额度体系天然是一条商业化路径（会员模型、额度包），但在教学场景中须守住底线：

- **教学基础能力永久免费**，不因商业化损害教学普惠性
- 校园合作可批量发放额度
- 参赛材料中说明此设计可强化「推广适配性」：BYOK 模式下**项目方零 token 成本**，任何学校、任何教师都可零成本接入自有模型使用

## 七、教学内容设计

智能体的教学行为必须与课程教学大纲严格对齐，否则将沦为空泛的技术演示（赛事红线一明确“拒绝空泛技术展示”）。

### 7.1 教学环节映射

延续论文已有的“课前预习—课堂教学—课后学习—实验实践”一体化模式，智能体在各环节的职责：

| 教学环节 | 通用功能 | 智能体增强 |
|---|---|---|
| 课前预习 | 浏览晶体、旋转缩放、查看参数 | 按预习任务主动引导：“今天要学 NaCl 结构，先自己转一转，然后回答我一个问题” |
| 课堂教学 | 手动演示 | 演示脚本自动编排、分步播放、一键复现（见 §4.3） |
| 课后学习 | 自主比较、查询参数 | 讲解 + 练习闭环 + 主动介入 + 错误可视化诊断（见 §4.1、§4.2） |
| 实验教学 | 理论模型与实验对照 | 智能体引导对比：“你的 XRD 结果里有这个峰，对应工具里的哪个晶面？” |

### 7.2 知识点—晶体—动作映射矩阵（节选）

这张矩阵是智能体教学能力的“教材”，也是能力图谱的数据基础。

| 知识点 | 代表晶体 | 典型 3D 观察动作 | 检测方式 |
|---|---|---|---|
| 点阵型式 | fcc / bcc / hcp / NaCl | 开启点阵点图层，观察点阵点分布 | 问：NaCl 的点阵型式？（答：面心立方 cF） |
| 堆积方式 | fcc(A1) / hcp(A3) / bcc(A2) | 切换 CPK 模型，开启面对角线/体对角线 | 问：A1 与 A3 的堆积差异？ |
| 配位环境 | NaCl(6:6) / CsCl(8:8) / ZnS(4:4) | 球棍模型 + 高亮中心原子及近邻 | 问：CsCl 的配位数？ |
| 空隙分布 | Cu 型 / Mg 型 | 开启八面体/四面体空隙图层 | 问：每个球周围几个八面体空隙？ |
| 空间群与对称元素 | 各晶体 | 开启对称元素图层 | 问：金刚石的空间群？ |
| 晶胞参数 | 各晶体 | 查看晶胞参数面板 | 问：给定晶胞参数算密度 |
| 结构基元 | NaCl / 金刚石 / 石墨 | 关闭对称展开（对称基元模式） | 问：NaCl 的结构基元含几个原子？ |
| 结构—性能关联 | 石墨 / 金刚石 / 石英 | 对比页并排展示 | 问：同为碳，为何性质差异巨大？ |

## 八、教学成效量化与埋点

对应评分项「实施显著性」25 分——**必须提供可验证、可核查的数据**。这是最容易失分也最容易得分的一项，关键是**尽早埋点、尽早积累**。

### 8.1 埋点指标体系

| 维度 | 指标 | 采集方式 |
|---|---|---|
| 使用规模 | 活跃用户数、新增用户数、日均会话数 | 前端埋点 |
| 使用深度 | 人均会话轮次、人均使用时长、人均查看晶体数、人均图层操作次数 | 前端埋点 |
| 智能体效能 | 主动介入触发次数、介入后响应率、工具调用成功率、诊断后重答正确率 | 前端埋点 |
| **练习板块专项** | 人均答题数、**首次正确率**、**答错后变式题正确率**（衡量是否真正纠正）、反向讲解完成率、晶体结构直达链接点击率 | 前端埋点 |
| 学习效果 | 章节测验成绩（实验班/对照班）、知识点掌握度提升幅度、错题复现率下降 | 测验 + 画像数据 |
| 教学效率 | 备课时长、课堂演示操作次数、教学脚本复用次数 | 访谈 + 日志 |
| 满意度 | 使用者满意度问卷（参考论文已有的问卷设计）、教师可用性评价 | 问卷 |

> **「答错后变式题正确率」是最有说服力的指标**——它直接衡量智能体是否真的帮使用者纠正了错误认知，而非只是提供了一个答案。这一指标在通用问答工具上无法获得（因为它们不出变式题）。

### 8.2 对照实验设计

推荐的最小可行实验设计：

- **对象**：山东大学结构化学课程（张冬菊教授课题组，已有小程序多轮试用基础）
- **分组**：实验班（使用智能体版）/ 对照班（仅使用无智能体版），或在同一班级内设置前后对照
- **测量**：晶体结构章节开始前的诊断测 + 章节结束后的测验
- **指标**：平均分差异、知识点掌握度分布差异、空间想象能力自评量表变化
- **样本**：建议不少于 60 人，越多越好

### 8.3 尽早启动

> **时间紧迫性提示**：赛事要求“拥有真实活跃用户基础”。智能体功能一旦可用（哪怕只是 §4.1 练习板块或 §4.2 的基础问答），**应立即挂到线上让真实使用者用起来**，不要等功能完备。三周内能积累的真实使用数据，比功能清单更能决定「实施显著性」的得分。

| 知识产权争议 | 触发淘汰红线 | 知识库不引入受版权保护的教材原文；所用模型/工具如实说明来源 |
| 教育数据出境合规 | 合规质疑 | 默认路径经自建后端代理且不传个人数据；BYOK 路径凭据不经服务器；材料中说明迁移计划 |
| 微信正式版不支持 AI | 两端叙事不成立 | **已明确为设计约束**：AI 能力以 H5 为唯一载体；小程序定位为数据基础与移动端交互佐证，skill 代码留待正式版开放后启用 |
| **额度被滥用刷量** | 平台 token 成本失控 | 服务端权威扣减 + 速率限制 + 异常模式检测；体验额度一次性约束；BYOK 分流重度使用者 |
| **BYOK 凭据泄漏** | 用户 API Key 泄露，信任崩塌 | 凭据只存本机、不入服务器、不进日志；掩码显示 + 一键清除；公共设备提供会话级存储选项 |
| **出题或答案有误** | 直接误导使用者，且比问答更严重 | 数值题一律由程序计算；概念题双源校验；答案与解析分离生成；入库前人工复核 |
| 模型输出不稳定 | 演示翻车 | 关键演示场景（视频录制）使用固定脚本；准备离线降级路径 |

## 十一、方案要点速览

> 若只能记住五句话：

1. **定位**：不是给工具加个聊天框，而是让智能体“看得见场景、动得了三维、讲得清知识点、练得会结构化学”。
2. **核心功能（问答练习板块）**：讲解 → 出题 → 点击作答 → 即时解析 → 一键跳回三维结构验证 → 答错深讲 → 变式题检验 → 反向复述，形成完整学习闭环。
3. **创新点（可解释的晶体学动作 + 错误可视化诊断）**：每个操控动作都绑定一个晶体学概念；答错时不直接给答案，而是把场景切换到能揭示错误根源的状态——通用问答模型做不到这两件事。
4. **防幻觉**：数值题一律由程序从 COD 数据集计算，结构参数只能经工具读取，模型没有编造的物理机会——正面回应赛事点名的幻觉痛点。
5. **落地**：以已上线的 H5 为载体（小程序受正式版 AI 能力限制作为配套佐证），在山大结构化学课程真实教学中试用，尽早埋点、尽早产生可量化数据。AI 为选用功能，支持额度与自带 Key（BYOK）两条路径。
