# 出题引擎技术设计

> 配套《AI智能体建设方案.md》§4.1 问答练习板块
> 编写日期：2026-09-22
> 本文是**设计文档**，描述结构、规则与流程，不含实现代码

---

## 一、设计目标与边界

### 1.1 三条硬约束

| 约束 | 来源 | 对设计的强制要求 |
|---|---|---|
| **题目与答案必须正确** | 出题比问答更危险——错误答案会被学生当标准答案记住 | 能计算的绝不交给模型；数据本身必须先校验 |
| **必须与三维场景耦合** | 赛事红线：区别于纯问答型大模型 | 每道题携带「预置观察状态」，可一键跳回结构验证 |
| **移动端可点击作答** | 目标用户以手机为主要终端 | 固定 4 选项、大按钮、无需输入 |

### 1.2 核心原则

> **能算的绝不问模型，能查的绝不算。**

具体分工：

- **数值、计数、几何量** → 由程序从晶体数据计算，模型完全不参与
- **字段直读的事实**（空间群、点阵型式、晶系） → 直接读数据
- **需要解释、比较、推理的内容** → 模型生成，但必须经三重校验
- **固定知识点**（如"每个球周围有 6 个八面体空隙"） → 内置知识表，不依赖数据也不依赖模型

## 二、可用原料盘点（基于 2026-09-22 实际数据核查）

出题引擎能吃多少原料，取决于数据层给了什么。以下是逐文件核查结果。

### 2.1 字段覆盖情况

| 字段 | 覆盖 | 出题用途 | 可用性 |
|---|---|---|---|
| `atoms[].positions` | 23/23 | 晶胞原子数、最近邻距离、坐标类题 | ✅ 直接可用 |
| `lattice` (a,b,c,α,β,γ) | 23/23 | 晶胞体积、密度、键长估算 | ✅ 直接可用 |
| `spaceGroup` | 23/23 | 空间群符号题 | ✅ 直接可用（见 §2.3 疑点） |
| `crystalSystem` | 23/23 | 晶系判断题 | ✅ 直接可用 |
| `symmetry.axes` / `.mirrors` | 23/23 | 对称元素题 | ✅ 直接可用 |
| `formula` | 23/23 | 摩尔质量、密度计算 | ✅ 可用（需化学式解析器） |
| `interstices` | 2/23 有内容 | 空隙数量题 | ⚠️ **仅 fcc、hcp 可出** |
| `spaceUtilization` | 3/23 | 空间利用率题 | ⚠️ 覆盖太低，宜改用内置知识表 |
| `latticeType` | 23/23 | 点阵型式题 | ⚠️ 见 §2.3 疑点 |
| `coordination` | 23/23 | 配位数题 | ❌ **格式不统一，不能直接解析**（见 §2.2） |
| `equivalentSettings` | 9/23 | 等效点系题 | ⚠️ 覆盖有限 |
| `bonds` / `covalentBonds` | 2/23, 4/23 | 成键题 | ⚠️ 覆盖有限 |
| `elements.js` 的 `atomicMass` | 103/103 | 摩尔质量计算 | ✅ 直接可用 |

### 2.2 关键发现：`coordination` 字段格式混乱

这是**出题引擎最重要的一个约束**。该字段的实际取值跨越了三种完全不同的格式：

| 格式类型 | 实例 | 涉及晶体 |
|---|---|---|
| 纯数字 | `"8"`、`"12"`、`"4"` | bcc、fcc、diamond |
| 半结构化 | `"Na, 6; Cl, 6"`、`"Cs, 8; Cl, 8"`、`"Cd²⁺, 6; I⁻, 3"` | naCl、csCl、cdi2 |
| 复杂自然语言 | `"Ca²⁺, 12 (O); Ti⁴⁺, 6 (O); O²⁻, 2 (Ca) + 2 (Ti)"` | perovskite、pyrite、rutile 等 |
| 纯描述（无数字） | `"分子晶体，无经典配位数"`、`"层内C-C共价键(配位数3)，层间van der Waals力"`、`"分子晶体，相邻水分子间以氢键连接"` | co2、graphite、i2、ice |

**结论：不能用正则从该字段提取数字出题。** 必须人工整理一张结构化的配位数对照表，例如：

```
晶体 → [{元素, 配位数, 配位构型, 近邻元素}]
naCl → [{Na, 6, 八面体, Cl}, {Cl, 6, 八面体, Na}]
csCl → [{Cs, 8, 立方体, Cl}, {Cl, 8, 立方体, Cs}]
co2  → []   // 分子晶体，无经典配位数 —— 这本身可出概念题
```

这张表是出题引擎的**人工资产**，也是人工复核的重点对象。工作量约 23 条，半天可完成。

> 顺带一提：分子晶体那几条纯描述文字并非无用——它们恰好可以出概念题（“为什么干冰晶体没有经典配位数？”），只是不能当数值题的数据源。

### 2.3 数据质量疑点（出题前必须核对）

程序算得对的前提是**数据本身是对的**。核查中发现两处需要人工确认：

| 晶体 | 疑点 | 建议 |
|---|---|---|
| `rhomboGraphite` | 空间群 `R-3m` 是 R 心点阵，但 `latticeType` 写作 `"R心六方(hP)"`。R 心点阵的规范记号应为 **hR**，中文"R心六方"与"(hP)"自相矛盾 | 核对后统一为 `R心六方(hR)` |
| `pyrite` | 空间群 `Pa-3` 是 **P（简单）点阵**，但 `latticeType` 写作 `"面心立方(cF)"`。若该字段表示"点阵型式"，应为 cP；若表示"Fe 亚晶格的排列方式"，则 cF 在教学语境下可接受 | 先明确定义该字段的语义，再核对 |

补充说明：`quartz` 的 `"简单三方(hP)"` 是**正确**的——P3₂21 属简单三方，用六方轴描述时记 hP。不要误改。

**这项核对的必要性**：如果不做，出题引擎会把数据里的疑点自动变成考题，把错误传递给学生——这比模型的幻觉更隐蔽，因为它是"程序算出来的"，反而更容易被信任。

### 2.4 由数据可直接计算的量（确定性，零幻觉）

| 计算量 | 公式/方法 | 覆盖 |
|---|---|---|
| 晶胞原子数 Z | Σ `atoms[].positions.length` | 23/23 |
| 晶胞体积 V | V = abc·√(1−cos²α−cos²β−cos²γ+2cosαcosβcosγ)，其余晶系为其特例 | 23/23 |
| 摩尔质量 M | 解析 `formula`，按 `elements.js` 的 `atomicMass` 求和 | 23/23 |
| 理论密度 ρ | ρ = Z·M / (N_A·V) | 23/23 |
| 最近邻距离 | 遍历 positions 计算最小距离（须考虑周期性镜像，取 27 个平移矢量中最短者） | 23/23 |
| 晶胞内空隙数 | `interstices[k].positions.length` | 仅 fcc(八面体4/四面体8)、hcp(八面体2/四面体4) |
| 对称轴清单 | 遍历 `symmetry.axes[].type` | 23/23 |

### 2.5 ⚠️ 两个必须区分的问法

数据里给的 `interstices` 数量是**晶胞内的空隙数**，不是"每个球周围的空隙数"。两者数值不同，混淆会出错误题目：

| 问法 | 答案来源 | fcc 的答案 |
|---|---|---|
| "Cu 型晶胞中含有几个八面体空隙？" | 读数据：`interstices.octahedral.positions.length` | **4** |
| "Cu 型中每个球周围有几个八面体空隙？" | 内置知识表（这是晶体学结论，不由晶胞数据决定） | **6** |

**设计要求**：题型模板中必须显式区分这两类问法，各自绑定不同的答案来源。这一类细节是出题引擎最容易出错、也最难被发现的地方。

## 三、双通道出题架构

```
出题请求（知识点 + 目标晶体 + 难度）
        │
        ├─ 该知识点有确定性生成器？
        │        │
        │        ├─ 是 ──→ 【通道 A】数据驱动题
        │        │           程序计算 → 标准答案
        │        │           干扰项从错因库反推
        │        │           解析由模板填充
        │        │           结果：答案物理上不可能错
        │        │
        │        └─ 否 ──→ 【通道 B】概念题
        │                    模型生成 → 三重校验
        │                    校验不过则丢弃重生成
        │
        └─ 输出统一题目对象（含预置观察状态）
```

### 3.1 通道 A：数据驱动题（优先）

**适用范围**：一切含数值、计数、几何量的题目。

**生成流程**：

1. 选定题型模板（见 §4.2）
2. 从晶体数据读取参数
3. 按模板的计算式算出标准答案
4. 从错因库（见 §5）反推 3 个干扰项
5. 按解析模板填充文字
6. 绑定预置观察状态
7. **自校验**：答案合理性检查（见 §4.5）

**可靠性**：答案是程序算出来的，不存在幻觉。**唯一风险源是数据本身的错误**，由 §2.3 的数据校验和 §4.5 的合理性检查兜底。

### 3.2 通道 B：概念题（兜底）

**适用范围**：解释性、比较性、推理性的题目，无法用公式表达。

**特点**：模型参与生成，但受三重校验约束（见 §6.2）。

**占比控制**：建议**概念题不超过总量的 30%**。数据驱动题既更可靠，也更能与三维场景耦合，应作为主体。

## 四、确定性生成器设计

### 4.1 生成器接口约定

每个题型模板是一个独立的生成器，接收统一的输入、产出统一的题目对象。

**输入**：`{ 知识点ID, 晶体ID, 难度层级, 变式种子 }`

**输出（题目对象）**：

| 字段 | 说明 |
|---|---|
| `id` | 题目唯一标识（含生成种子，保证可复现） |
| `stem` | 题干 |
| `options` | 4 个选项，每项含 `text` 与 `errorCause`（正确项的 errorCause 为空） |
| `answerIndex` | 正确选项的下标 |
| `explanation` | 解析文本（正误说明 + 错项逐个分析） |
| `knowledgePoint` | 知识点节点 ID（C1–C8） |
| `difficulty` | L1–L4 |
| `crystalId` | 关联晶体 |
| `presetView` | 预置观察状态（见 §8） |
| `source` | `data`（通道 A）或 `model`（通道 B） |
| `reviewStatus` | `generated` / `approved` / `rejected` |

### 4.2 题型模板库

按知识点组织。每类给出：题干模板、答案来源、适用晶体范围、可行性评级。

| "{name} 属于哪个晶系？" | 读 `crystalSystem` | 23/23 | ✅ |
| "{name} 的点阵点是 {P/I/F/C/R} 型吗？" | 从 `latticeType` 括号内符号判定 | 23/23 | ⚠️ 同上 |

| "{A} 与 {B} 的密度之比是多少？" | 分别计算 | ✅ |

### 4.3 干扰项生成规则（核心设计）

**这是出题引擎区别于普通题库的关键。** 干扰项不是随机数，而是**从典型错误认知反推出来的**——因此每个错误选项都携带诊断信息，学生选错时能立刻知道他错在哪一类。

三类干扰策略：

| 策略 | 适用 | 示例 |
|---|---|---|
| **错因反推**（首选） | 有明确典型错因的题 | 问"每个球周围几个八面体空隙"，正确答案 6，干扰项含 8（把八面体的面数当空隙数） |
| **邻近值** | 数值题无明确错因时 | 正确答案 4 → 干扰项 2、6、8 |
| **邻近概念** | 选项为概念时 | 正确答案"面心立方(cF)" → 干扰项"体心立方(cI)"、"简单立方(cP)"、"底心正交(oC)" |

**干扰项生成硬规则**：

1. 必须 4 个选项，**恰好 1 个正确**
2. 干扰项**不得与正确答案数值相等**（邻近值策略下必须去重）
3. 干扰项之间不得重复
4. 数值干扰项须在**合理量级**内（不得出现明显荒谬的数值）
5. 优先生成"有错因标签"的干扰项；错因不足时才用邻近值填充

### 4.4 解析模板

每个题型模板配套一个解析生成规则，输出三段：

1. **正误说明**：为什么正确选项对
2. **错项逐个分析**：每个干扰项对应哪个错因，为什么错
3. **结构指引**：引导去看哪个三维观察动作

示例（填空形式，由程序填充数值）：

> 正确答案是 **6**。A1/A3 最密堆积中，每个球周围有 6 个八面体空隙，它们位于球的上下各 3 个位置。
> · 选 **8** 的话：这是八面体的**面数**，不是空隙数——空隙个数由堆积方式决定，与多面体的顶点/面数无关。
> · 选 **4** 的话：这是晶胞内**八面体空隙的总数**（对应 4 个球），不是单个球周围的数目。
> · 选 **12** 的话：这是**配位数**，问的是近邻原子数，不是空隙数。
> 👉 点下方按钮，把空隙图层打开自己数一数。

### 4.5 自校验（生成后自动执行）

生成器产出题目后，自动跑一遍合理性检查，任一项不通过则丢弃并换参数重生成：

| 检查项 | 规则 |
|---|---|
| 答案量级 | 数值答案须在物理合理范围（如密度 0.1–25 g/cm³） |
| 选项唯一性 | 4 个选项互不相同 |
| 答案存在于选项中 | `options[answerIndex].text` 与计算值一致 |
| 答案合理性 | 计数量须为正整数且在合理上限内（如配位数 ≤ 12 多数情况） |
| 化学式解析 | 摩尔质量计算成功且落在合理范围 |
| 与知识库一致 | 若该题涉及固定知识点，须与内置知识表相符 |

> **与内置知识表的交叉校验尤为关键**：例如程序算出 A1 的空间利用率为 74.05%，须与内置知识表比对；若因数据问题算出 68%，则说明晶格参数或半径数据有误，应报错而非出题。

## 五、错因分类体系

错因是干扰项的来源，也是答错后诊断动作的依据。设计与干扰项生成共用一张表。

### 5.1 四级错误类型

| 类型 | 说明 | 典型表现 |
|---|---|---|
| **E-A 概念混淆** | 把相近概念记混 | 八面体的面数 vs 空隙数；A1 vs A3 层序；cF vs cI |
| **E-B 计数错误** | 计数对象或范围弄错 | 晶胞内总数 vs 单个球周围；忘除结构基元 |
| **E-C 计算失误** | 公式用错或步骤遗漏 | 密度公式漏乘 Z；体积公式用错晶系特例 |
| **E-D 空间想象偏差** | 三维关系判断错误 | 以为 4 配位共面；把层间距离当最近邻 |

### 5.2 错因库（示例，需在开发中扩充）

| 错因 ID | 类型 | 错误认知 | 产生的干扰项 | 诊断动作 |
|---|---|---|---|---|
| E-A1 | 概念混淆 | 把八面体的面数(8)当成空隙数 | 8 | 打开八面体空隙图层，逐个数 |
| E-A2 | 概念混淆 | 把 A1 与 A3 的层序记反 | 立方最密堆积 ↔ 六方最密堆积互换 | 切换两个晶体并排对比 |
| E-A3 | 概念混淆 | 把点阵型式与晶系混为一谈 | 立方晶系 ↔ 面心立方 | 打开点阵点图层 |
| E-A4 | 概念混淆 | 把配位数与空隙数混 | 12 或 6 互换 | 高亮近邻原子 |
| E-B1 | 计数错误 | 用晶胞内总数代替单个球周围的数目 | 4（fcc 晶胞内八面体空隙总数） | 高亮单个球及其周围空隙 |
| E-B2 | 计数错误 | 忘记除以结构基元的原子数 | 原子总数代替结构基元数 | 切换对称基元/完整晶胞显示模式 |
| E-C1 | 计算失误 | 密度公式漏乘 Z | Z 倍偏差的数值 | 分步展示计算过程 |
| E-C2 | 计算失误 | 体积公式误用立方特例 | 按 a³ 计算的体积 | 切换到晶胞参数面板 |

### 5.3 错因 → 诊断动作 映射

答错后的流程是：**判定错因 → 执行对应诊断动作（操控三维场景）→ 追加讲解 → 变式题检验**。

诊断动作复用 `scene-bridge` 的受控动作（见主方案 §3.2），每个错因绑定一组动作序列。上表最后一列即为该绑定。

## 六、概念题生成与校验（通道 B）

### 6.1 生成流程

1. 组装上下文：知识点 + 晶体数据（以只读形式注入）+ 内置知识表相关条目
2. 模型生成题目（题干、4 选项、答案、解析、错因标签）
3. 执行三重校验（§6.2）
4. 通过则入库；不通过则携带失败原因重生成，最多重试 3 次
5. 3 次均失败则**降级为数据驱动题**或跳过该题

### 6.2 三重校验

| 校验 | 内容 | 不通过的处理 |
|---|---|---|
| **I. 格式校验** | 4 个选项、1 个答案、字段完整、无重复选项 | 直接丢弃 |
| **II. 事实校验** | 题目涉及的一切数值与事实，须能在晶体数据或内置知识表中找到依据；**禁止模型自行引入数值** | 丢弃并标记 |
| **III. 知识点归属校验** | 题目确属所声明的知识点节点 | 重新标注或丢弃 |

**第 II 项是本设计的核心防线**：模型生成的概念题**不允许包含任何未经数据验证的数值**。若题目需要数值（如"金刚石的密度约为 3.5 g/cm³"），该数值必须由数据计算提供，模型只能引用、不能生成。

### 6.3 答案与解析分离生成

**先冻结答案，再生成解析。** 这是防止"解析与答案互相圆场"的关键——如果让模型一次性输出题目、答案和解析，当答案本身错误时，解析会为错误答案编造一套自洽的理由，这种错误极难被发现。

实现方式：
1. 第一步：仅生成题干、选项、正确答案（不含解析）
2. 第二步：将已确认的答案作为**只读输入**，要求模型生成解析
3. 校验解析中出现的数值与第一步的答案一致

## 七、变式题生成规则

答错并讲解后，出一道**同知识点的变式题**检验是否真正纠正。变式维度如下：

| 变式维度 | 说明 | 示例 |
|---|---|---|
| **换晶体**（首选） | 同一知识点换一个晶体 | 从 Mg 型换到 Cu 型问同一问题 |
| **换问法** | 同一数据换个角度问 | 从"每个球周围"换为"晶胞内共有几个" |
| **换参数** | 数值题换参数 | 换另一种晶体的晶格参数求密度 |
| **反向提问** | 已知答案反推条件 | 已知空间利用率反推堆积类型 |

**选变式的规则**：
- 若首次错因是 **E-A（概念混淆）** → 用**换晶体**，检验概念是否泛化
- 若首次错因是 **E-B（计数错误）** → 用**换问法**，直接检验是否分清了两种问法
- 若首次错因是 **E-C（计算失误）** → 用**换参数**，检验公式是否掌握
- 若首次错因是 **E-D（空间想象）** → 用**换晶体 + 强制看三维场景**

**这是「答错后变式题正确率」这一指标的技术基础**——该指标是衡量智能体是否真正帮学生纠正认知的最有说服力证据（见主方案 §8.1）。

### 8.1 `presetView` 结构（描述）

## 九、难度分级

| 层级 | 认知层次 | 特征 | 数据来源 |
|---|---|---|---|
| **L1** | 记忆 | 单一字段直读 | 读 `spaceGroup`、`lattice.a` |
| **L2** | 理解 | 简单计数或单步计算 | 数原子数、算体积 |
| **L3** | 应用 | 多步计算或空间推理 | 算密度、找最近邻、算空隙占比 |
| **L4** | 分析 | 跨晶体比较、结构-性能关联 | 概念题为主，或混合式 |

**难度与知识点的关系**：同一知识点可跨多个难度出题。例如 C7 晶胞参数：L1 问 a 是多少，L2 算体积，L3 算密度，L4 比较两种同素异形体的密度差异。

**自适应规则**：依学情画像动态选题——某知识点连续答对 2 题则升一级，连续答错 2 题则降一级。

## 十、数据校验层

鉴于 §2.3 发现的疑点，出题引擎**必须**包含一个独立的数据校验层，在启用出题前运行一次，并支持随时重跑。

### 10.1 校验项

| 校验 | 规则 | 处理 |
|---|---|---|
| 点阵型式 vs 空间群 | 空间群首字母与 `latticeType` 的 P/I/F/C/R 记号一致性 | 报告不一致，人工裁定 |
| 莫尔质量合理性 | 由 `formula` 算出的 M 须与元素组成相符 | 报错 |
| 空间利用率交叉校验 | 由半径与晶格参数算出的利用率，须与内置知识表相符（容差 1%） | 报错并标注数据可疑 |
| 原子坐标范围 | 分数坐标应在 [0, 1) 区间内 | 警告 |
| 最近邻距离合理性 | 计算出的最近邻距离应接近两原子半径之和（容差 30%） | 警告 |
| 空隙位置有效性 | 空隙坐标不应与原子坐标重合 | 警告 |
| 化学式可解析 | 所有晶体的 `formula` 均可被解析器正确解析（含括号嵌套如 `CO(NH₂)₂`） | 报错 |

### 10.2 校验产物

校验报告应作为**项目管理文档保留**，理由有二：

1. 开发期用于定位问题
2. **参赛材料中可作为「技术规范性」的佐证**——展示作品在数据准确性上有主动的质量控制流程，而非直接信任原始数据
